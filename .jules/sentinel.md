## 2024-10-18 - [SSRF/Open Redirect via Loose Domain Validation]
**Vulnerability:** `isValidUrl` and `sanitizeUrl` in `src/sanitizers/url.ts` used `.includes('evzone.com')` and `parsed.hostname.includes('evzone')` for domain validation. This allowed SSRF/Open Redirect bypasses via URLs like `https://attacker-domain.com?q=evzone.com` or `https://evzone.com.attacker.com`. Additionally, malicious payloads with the `javascript:` protocol (e.g., `javascript:alert(1)//evzone.com`) could parse with empty hostnames and bypass protocol allowlists if not strictly enforced.
**Learning:** `URL.hostname` includes subdomains and `.includes()` performs substring matching across the entire hostname or even query parameters if not careful. `new URL()` behavior with `javascript:` payloads can bypass standard checks.
**Prevention:** Enforce strict equality (`=== 'domain.com'`) or strict suffix matching (`.endsWith('.domain.com')`) for subdomains. Ensure a strict protocol allowlist is evaluated before any hostname checks. Strip whitespace to prevent newline/tab injection, and explicitly handle safe relative paths if required.
