## 2024-07-04 - SSRF and Open Redirect via Naive URL Validation
**Vulnerability:** The `isValidUrl` and `sanitizeUrl` functions in `src/sanitizers/url.ts` were vulnerable to Server-Side Request Forgery (SSRF), Open Redirect, and Cross-Site Scripting (XSS). They used naive `.includes('evzone.com')` matching for domains, allowing bypasses like `https://evzone.com.attacker.com`. They also failed to strictly check protocols first, allowing parsed URLs to bypass validation when Javascript protocols or malformed URLs were passed.
**Learning:** Naive substring matching for URLs (like `.includes()`) is highly vulnerable to subdomain and sibling domain bypasses. Additionally, using `new URL()` in JS without an initial strict protocol check (`http:`, `https:`) allows malformed URIs (e.g., `javascript:alert(1)//evzone.com`) to parse and bypass domain-only checks. The application relies heavily on `window.location.assign()`/`href`, making URL validation critical.
**Prevention:** Always use exact matching or strict Regex for domain validation, anchored to the end of the hostname (e.g., `/^([a-z0-9-]+\.)*(evzone\.com)$/i`). Strictly check allowed protocols (`['http:', 'https:'].includes(parsed.protocol)`) *before* checking the hostname. Finally, explicitly handle and allow safe relative paths while stripping whitespace injection bypasses (`\n`, `\r`, `\t`).
