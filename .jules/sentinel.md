## $(date +%Y-%m-%d) - Fix SSRF and Open Redirect Vulnerabilities in URL Sanitizer
**Vulnerability:** The `isValidUrl` and `sanitizeUrl` functions in `src/sanitizers/url.ts` were vulnerable to Server-Side Request Forgery (SSRF), Open Redirects, and Cross-Site Scripting (XSS). `isValidUrl` allowed bypassing validation by using a substring match `.includes('evzone.com')`, which allowed domains like `attacker-evzone.com` or `evzone.com.attacker.com`. `sanitizeUrl` allowed arbitrary protocols (e.g., `javascript:`, `data:`), making it vulnerable to XSS. It also threw exceptions for relative paths, which could break SPA routing.
**Learning:** URL validation and sanitization are common sources of vulnerabilities. Using substring matches for hostname verification is insufficient. Browsers are lenient and parse `javascript:` protocols even with whitespace. The URL constructor throws errors for relative paths, which need to be handled explicitly.
**Prevention:** Always use strict equality (`===`) or strict suffix matching (`.endsWith('.evzone.com')`) for hostnames. Enforce a strict protocol allowlist (`['https:', 'http:']` for `isValidUrl` and `['https:', 'http:', 'mailto:', 'tel:']` for `sanitizeUrl`). Strip whitespace from the input and explicitly allow safe relative paths (starting with `/`, `?`, or `#`, while rejecting `//` and `/\`) before passing to the `URL` constructor.
