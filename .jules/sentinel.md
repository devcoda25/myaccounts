## 2026-10-29 - [Insecure URL Validation via Substring Matching]
**Vulnerability:** The codebase was using `.includes()` on hostnames (e.g., `parsed.hostname.includes('evzone.com')`) for URL validation, which allows Server-Side Request Forgery (SSRF) and Open Redirect bypasses by matching malicious domains like `evzone.com.attacker.com`. It also lacked whitespace sanitization and strict protocol checks before hostname validation, exposing potential XSS via `javascript:` URIs.
**Learning:** The URL API's `.hostname` must never be validated with loosely matched string methods like `.includes()` because domain structures are hierarchical from right to left, making prefix or substring matches insecure. Furthermore, the `URL` constructor does not reject `javascript:` URIs, leading to empty hostnames that bypass validation if a protocol allowlist isn't checked first.
**Prevention:** Always strip whitespace characters first, enforce an explicit protocol allowlist (e.g., `['http:', 'https:']`) before hostname validation, and use exact matching (`===`) or strict suffix matching (`.endsWith('.domain.com')`) to validate safe domains.
