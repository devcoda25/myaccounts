## 2024-05-15 - [CRITICAL] Fix URL Validation SSRF/Open Redirect Bypass
**Vulnerability:** The `isValidUrl` and `sanitizeUrl` functions used insecure hostname matching (`.includes('evzone.com')` and `.includes('evzone')`) and failed to strip whitespace or enforce strict protocols during URL parsing, allowing bypasses like `attacker-evzone.com` or `javascript:alert(1)//evzone.com`.
**Learning:** Using `.includes` for domain validation is fundamentally flawed as it matches malicious prefixes/suffixes. Additionally, unstripped whitespace can bypass URL parser checks, and `new URL()` throws on safe relative paths, which breaks legitimate client-side routing if not handled explicitly.
**Prevention:** Always use strict equality (`=== 'domain.com'`) combined with suffix matching (`.endsWith('.domain.com')`) for subdomains. Strip whitespace before parsing (`.replace(/[\n\r\t]/g, '').trim()`), explicitly allow safe relative paths (`.startsWith('/') && !.startsWith('//') && !.startsWith('/\\')`), and enforce strict protocol allowlists.
