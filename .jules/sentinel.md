## 2024-05-25 - [Open Redirect via Weak URL Validation]
**Vulnerability:** Open Redirect and SSRF bypass via insecure domain validation. The validation logic used `parsed.hostname.includes('evzone.com')`, which would incorrectly authorize malicious URLs like `evzone.com.attacker.com` and `attacker.com/evzone.com`. Additionally, redirect locations like `ctx.redirectUri` were passed into `window.location.href` entirely unvalidated.
**Learning:** `String.prototype.includes()` is dangerously weak for URL hostname validation. Bypassing it is trivial when validating dynamic client-side parameters, potentially leaking the `code` and `state` OAuth parameters to attackers.
**Prevention:** Strictly validate domains using exact matches or strict regex checks such as `/^([a-z0-9-]+\.)*(evzone\.com|evzone\.app|evzonemarketplace\.com)$/i`. Consistently enforce this URL verification helper function (e.g., `isValidUrl`) across all logic branches before assigning external redirects to `window.location.href`.
