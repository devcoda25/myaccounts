## 2024-06-05 - Open Redirect and SSRF Bypass via Weak URL Validation
**Vulnerability:** The `isValidUrl` function in `src/sanitizers/url.ts` used weak string matching (`parsed.hostname.includes('evzone.com')`) and did not strip whitespace before parsing, allowing attackers to bypass validation using domains like `evzone.com.attacker.com` or injecting newline/tabs before protocols like `javascript:`. This allowed for Open Redirect and SSRF via parameters like `redirect_uri` which were assigned directly to `window.location.href`.
**Learning:** `URL` constructor parsing behavior and JavaScript's `.includes()` are insufficient for strict domain validation. The `URL` constructor will happily parse URLs with newlines preceding the protocol or treat `javascript:` as the protocol even when trailing slashes and a domain are provided.
**Prevention:** Always strip whitespace characters (`\n`, `\r`, `\t`) before parsing with the `URL` constructor. Use strict regex matching against a trusted allowlist to validate domains rather than weak string inclusion. Additionally, always fallback to safe internal routing (e.g., `navigate('/app')`) if validation fails instead of relying on default unsafe redirects.
