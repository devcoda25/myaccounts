## 2026-06-26 - [CRITICAL] Fix URL Validation Bypass (SSRF / Open Redirect / XSS)
**Vulnerability:** URL parser constraints in `src/sanitizers/url.ts` permitted SSRF, Open Redirect, and XSS. Validation relied on `.includes('evzone.com')` causing subdomains or suffixes like `evzone.com.attacker.com` to falsely pass. Furthermore, protocols were not strictly validated, allowing `javascript:alert(1)//evzone.com` to slip by as the native URL constructor validates `javascript:` as a valid protocol and assigns it an empty hostname.
**Learning:** Naive substring matching for domains is critically vulnerable. JavaScript's native `URL` constructor does not enforce HTTP/HTTPS by default, allowing untrusted protocols to bypass sanitizers if not strictly checked first. Control characters like `\n` or `\r` can also spoof the constructor.
**Prevention:** Always use strict Regex (e.g. `/^([a-z0-9-]+\.)*(domain\.com)$/i`) rather than `includes()` for domains. Strip whitespace characters `[\n\r\t]` before parsing. Explicitly restrict `parsed.protocol` to an allowlist (e.g. `['http:', 'https:', 'mailto:', 'tel:']`).
