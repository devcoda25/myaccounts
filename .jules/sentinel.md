## 2024-11-20 - [Fix SSRF/Open Redirect in URL Sanitizers]
**Vulnerability:** URL validators (`isValidUrl` and `sanitizeUrl`) used weak domain matching (`.includes('evzone.com')`), allowing domain spoofing bypasses (e.g. `attacker.com/evzone.com` or `evzone.com.attacker.com`). Furthermore, `sanitizeUrl` failed to strictly validate URL protocols before reconstruction, creating Cross-Site Scripting (XSS) risks via `javascript:` payloads.
**Learning:** Overly permissive domain checks such as `.includes()` are insufficient for security boundaries. Furthermore, URL parsers can successfully parse malicious schemas, requiring an explicit protocol allowlist check before passing the data to application sinks.
**Prevention:** Always combine exact domain matching (`===`) with strict suffix matching (`.endsWith('.domain.com')`) for safe subdomain handling. Enforce strict protocol allowlists (`['https:', 'http:']`) before trusting parsed URL content. Defend against protocol-relative URL parser bypasses by ensuring relative paths start with a single forward slash and avoiding `//` or `/\`.
