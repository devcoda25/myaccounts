## 2024-07-02 - [CRITICAL] Open Redirect / SSRF in ContinueToApp via weak URL validation
**Vulnerability:** The application used a weak string inclusion check (`.includes('evzone.com')`) for validating redirect destinations and omitted the check entirely before modifying `window.location.href` in the ContinueToApp feature. This allowed attackers to bypass domain validation (e.g., using `https://evzone.com.attacker.com` or injecting whitespace like `\n`) resulting in Open Redirect or SSRF.
**Learning:** Naive validation using `includes()` or unanchored matching for domain names is fundamentally insecure as it fails to account for subdomain chaining or manipulated payloads in the JS `URL` constructor.
**Prevention:** Always use strict regex (e.g. `/^([a-z0-9-]+\.)*(evzone\.com|evzone\.app|evzonemarketplace\.com)$/i`) for domain validation, explicitly sanitize inputs by stripping whitespace (`/ [\n\r\t ]/g`), allowlist permitted protocols (`https:`, `http:`), safely manage relative paths, and consistently validate URLs immediately prior to assignment.
