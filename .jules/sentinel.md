## 2026-11-02 - Strict URL Validation and Sanitization Bypass
**Vulnerability:** `isValidUrl` and `sanitizeUrl` use loose `.includes()` checks for hostnames (e.g. `.includes('evzone.com')`), allowing SSRF/Open Redirect bypasses like `evzone.com.evil.com`. Furthermore, `sanitizeUrl` returns the original parsed URL if it's not HTTPS and doesn't include 'evzone', which allows XSS via `javascript:alert(1)` because `new URL()` parses the `javascript:` protocol without throwing.
**Learning:** `new URL()` does not throw errors for unexpected protocols like `javascript:`. Using `.includes()` for domain validation is insecure as it matches substrings, enabling attackers to register domains containing the target string as a subdomain or part of the name.
**Prevention:** Always strip whitespace characters first to prevent injection bypasses. Enforce a strict protocol allowlist (e.g. `['http:', 'https:']`) explicitly before any hostname validation. Do not use `.includes()` for domains; use exact matching (`===`) or strict suffix matching (e.g. `.endsWith('.domain.com')`).
