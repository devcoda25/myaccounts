## 2025-02-18 - SSRF and Open Redirect via Insecure URL Validation
**Vulnerability:** The URL validation utilities (`isValidUrl` and `sanitizeUrl`) were vulnerable to Server-Side Request Forgery (SSRF) and Open Redirect due to insecure domain validation (`.includes('evzone.com')`) which allowed attacker domains like `evzone.com.attacker.com`. Additionally, `sanitizeUrl` did not enforce a protocol allowlist, permitting malicious protocols like `javascript:alert(1)`. Both functions were also vulnerable to URL parsing bypasses via whitespace injection (`%0A`, `%0D`, `%09`).
**Learning:** Using `.includes()` or naive string matching for domain validation is insecure and easily bypassed. The JavaScript `URL` constructor allows whitespace characters in certain contexts which can lead to parsing inconsistencies between the frontend and backend, or bypass naive domain checks. Protocols must always be strictly allowlisted.
**Prevention:** Always use strict regular expressions with start/end anchors (`^...$`) or exact string matching (`===`) for domain validation. Strip whitespace characters (`/[\n\r\t]/g`) before parsing URLs. Implement a strict protocol allowlist (e.g., `['http:', 'https:', 'mailto:', 'tel:']`) for any URL sanitization function.
