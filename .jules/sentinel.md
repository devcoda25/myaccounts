## 2024-06-08 - String Includes is not URL Validation

**Vulnerability:** Open Redirect and potential SSRF bypasses via naive `.includes()` checks for URL validation. Specifically, the application was using `parsed.hostname.includes('evzone.com')`, which would incorrectly allow domains like `evzone.com.attacker.com` or `attacker.com?evzone.com`. Additionally, there was a Path Traversal / Open Redirect vector in path segment validation via `!segment.includes("/")` which could be bypassed by using backslashes `\`. Finally, JavaScript URI's could bypass basic checks if newline characters were injected (e.g. `javascript://%0Aalert(1)`).

**Learning:** URL hostnames match from right-to-left, meaning prefix matches (`evzone.com.attacker.com`) are not subdomains, but entirely different domains. Additionally, `.includes('/')` is insufficient for ensuring a string contains only a single path segment because backslashes `\` are also evaluated as directory separators in many URL parsing contexts. Finally, the Javascript URI protocol is incredibly robust, ignoring whitespace and newlines, allowing for bypasses when naively checked or passed to `new URL()`.

**Prevention:** Always use strict regex matching for domain validation, ensuring the domain ends exactly with the target host (`/^(.*\.)?evzone\.com$/i`). To validate dynamic URL segments against directory traversal characters, strictly enforce an allowlist regex (e.g., `/^[a-zA-Z0-9-_]+$/`) rather than blocking specific substring characters. Also, always sanitize strings to remove newline/carriage-return and strictly enforce protocol allowlists.
