## 2026-09-24 - [CRITICAL] Fix URL Sanitizer SSRF/XSS Bypass
**Vulnerability:** The `isValidUrl` and `sanitizeUrl` functions used `.includes('evzone')` to validate hostnames, allowing SSRF/Open Redirects via subdomains like `attacker-evzone.com` or `evzone.com.attacker.com`. Additionally, `sanitizeUrl` did not restrict protocols, allowing XSS vectors like `javascript:alert(1)` to bypass validation.
**Learning:** Broad matching functions like `.includes()` are inherently insecure for URL validation, as they do not respect hostname boundaries. Furthermore, the `URL` constructor parses the `javascript:` protocol, necessitating an explicit protocol allowlist to prevent XSS.
**Prevention:** Always use strict equality (`===`) for exact domains and strict suffix matching (`.endsWith('.domain.com')`) for subdomains. Enforce a strict protocol allowlist (e.g., `['http:', 'https:']`) *before* executing domain logic. Always strip whitespace characters (e.g., `[\n\r\t]`) prior to URL parsing.
