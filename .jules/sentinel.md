## 2024-05-24 - Fix SSRF and Open Redirect Vulnerability in URL Sanitizers
**Vulnerability:** The isValidUrl and sanitizeUrl utilities relied on .includes('evzone.com') for hostname validation, which allows bypasses using malicious domains like attacker-evzone.com or evzone.com.attacker.com. Additionally, sanitizeUrl failed to strictly enforce a protocol allowlist, permitting dangerous protocols like javascript: and potentially breaking safe relative paths.
**Learning:** Broad subdomain checks (.includes()) and missing protocol allowlists in URL parsing functions can be trivially bypassed to achieve SSRF, Open Redirects, or XSS. Furthermore, the URL constructor does not handle relative paths without throwing an error.
**Prevention:** Always use strict equality (=== 'domain.com') combined with strict suffix matching (.endsWith('.domain.com')) for hostnames. Implement strict protocol allowlists (e.g., http:, https:), strip whitespace to prevent injection bypasses, and explicitly handle safe relative paths.
