## 2024-05-21 - [HIGH] XSS and SSRF in URL Sanitization
**Vulnerability:** The application used `.includes('evzone.com')` for domain validation and allowed implicit assignment of dangerous protocols like `javascript:` by modifying `protocol` property on invalid URLs. This permitted SSRF/Open Redirects (e.g. `evzone.com.attacker.com`) and XSS attacks via `javascript:` protocols.
**Learning:** Naive substring matching for domains is vulnerable to prefix/suffix bypasses. When using the `URL` constructor, reading or modifying the `protocol` property does not fail safely for unsupported schemas like `javascript:`, bypassing subsequent domain logic. Furthermore, relative paths throw errors in `new URL()`, necessitating explicit handling rather than catching and defaulting to empty strings.
**Prevention:** Always use strict regex matching (`/^([a-z0-9-]+\.)*(evzone\.com|evzone\.app|evzonemarketplace\.com)$/i`) for domain validation, explicitly validate URL protocols against an allowlist (`http:`, `https:`, `mailto:`, `tel:`), and explicitly manage safe relative path fallbacks during exception handling to avoid functional regressions.
