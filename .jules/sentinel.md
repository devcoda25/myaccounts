## 2024-05-29 - [CRITICAL] Fix Open Redirect and XSS via Weak URL Validation
**Vulnerability:** The application was vulnerable to Open Redirects and XSS attacks due to weak URL validation. The `isValidUrl` function merely checked if `.includes('evzone.com')` was present in the hostname, allowing attackers to bypass the check with payloads like `https://evzone.com.attacker.com`. Additionally, `sanitizeUrl` did not restrict protocols against an allowlist, making it susceptible to `javascript:` payloads where the browser parses an empty hostname. Unvalidated redirect URIs were also directly assigned to `window.location.href` in authentication flows.
**Learning:** Naive string matching (`.includes()`) is insufficient for domain validation and easily circumvented. Furthermore, the `URL` API does not inherently sanitize malicious schemes (like `javascript:`); it blindly assigns them and will pass checks that don't explicitly validate the scheme against an allowlist.
**Prevention:** Always use strict regex matching or exact equality `===` for domain allowlisting. Additionally, when sanitizing URLs, explicitly validate the protocol against a strict allowlist (e.g., `['http:', 'https:', 'mailto:', 'tel:']`). When assigning dynamic values to `window.location.href`, ensure they are validated by the robust URL utility functions with a secure internal fallback (like React Router's `navigate`).
