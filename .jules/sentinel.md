## 2026-06-28 - [Strict Regex for URL Validation]
**Vulnerability:** The `isValidUrl` function used `.includes()` which was vulnerable to Open Redirect and SSRF bypasses via malicious subdomains like `evzone.com.attacker.com`. Also, the function threw TypeErrors on safe relative paths, which could break client-side routing. Finally, passing malicious URLs like `javascript:alert(1)//evzone.com` to `new URL()` didn't throw an error, circumventing naive hostname validation.
**Learning:** Checking for substrings using `.includes()` on domain validation is insufficient. The `URL` constructor parsing doesn't fail on safe relative paths or on malicious payloads if the protocol isn't strictly verified before or simultaneously with the hostname.
**Prevention:** Always use strict regex matching to validate domains (e.g., `/^([a-z0-9-]+\.)*(evzone\.com|evzone\.app|evzonemarketplace\.com)$/i`). Explicitly allow safe relative paths `(cleanUrl.startsWith('/') && !cleanUrl.startsWith('//') && !cleanUrl.startsWith('/\'))` and verify the protocol (`['https:', 'http:']`) before hostname verification. Clean URLs of whitespace characters before parsing.
