## 2026-09-18 - URL Parsing and Validation Vulnerabilities
**Vulnerability:** URL parsing functions used `.includes()` for domain validation, allowing SSRF/Open Redirects via malicious domains (e.g., `attacker-evzone.com`). The URL constructor also parsed malicious payloads starting with whitespace (e.g., `\njavascript:alert(1)`) without error, bypassing protocol checks if they implicitly relied on empty hostnames.
**Learning:** The built-in `URL` constructor in JavaScript is permissive with leading whitespaces and handles special protocols like `javascript:` unexpectedly by returning empty hostnames. String `.includes()` matching for domains is insecure because it permits malicious domains that contain the target domain as a substring.
**Prevention:** Always strip whitespace characters (`url.replace(/[\n\r\t]/g, '').trim()`) before passing input to the `URL` constructor. Enforce strict protocol allowlists. Validate subdomains using strict equality (`===`) and strict suffix matching (`.endsWith('.domain.com')`) instead of substring matching.
