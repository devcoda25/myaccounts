## 2026-10-03 - [CRITICAL] Prevent URL Parsing Bypasses in Sanitizers
**Vulnerability:** The `isValidUrl`, `sanitizeUrl`, and `extractHostname` functions in `src/sanitizers/url.ts` pass raw strings to `new URL()` without pre-stripping whitespace or enforcing absolute URLs strictly before property access. This allows payload bypasses like `  javascript://evzone.com/%0Aalert(1) ` which evades the initial `isValidUrl` checks if the protocol check is not strictly enforced first, and `extractHostname` doesn't validate protocols at all, returning `evzone.com` for the javascript payload.
**Learning:** `new URL()` strips leading/trailing whitespace automatically but its protocol parsing can be tricked if protocol enforcement isn't done correctly. Furthermore, checking `hostname.includes('evzone.com')` without first strictly validating the protocol allows XSS vectors using the `javascript:` protocol with a fake hostname (e.g. `javascript://evzone.com/...`).
**Prevention:** Always strip whitespace characters first (e.g. `url.replace(/[\n\r\t]/g, '').trim()`) to prevent newline/tab injection bypasses. Then, explicitly enforce a strict protocol allowlist (`['http:', 'https:']`) BEFORE any further validation or returning the parsed string.
