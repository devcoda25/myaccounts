## 2026-08-23 - [Strict URL Validation to Prevent SSRF/Open Redirect]
**Vulnerability:** The `isValidUrl` and `sanitizeUrl` functions used `.includes('evzone.com')` for domain validation, allowing bypasses via malicious domains like `evzone.com.attacker.com` or `attacker-evzone.com`. They also failed to strip whitespace characters before parsing, allowing payload injection, and lacked strict protocol enforcement for `sanitizeUrl` (allowing `javascript:` via relative paths).
**Learning:** Using loose matching like `.includes()` on hostnames is a critical pattern that permits Server-Side Request Forgery (SSRF) and Open Redirects. `new URL()` accepts whitespace like newlines in malicious payloads which bypass simple checks. Safe relative URLs can also be broken by strict `new URL()` usage if not handled gracefully.
**Prevention:** Always strip whitespace (`[\n\r\t]`) from URLs before parsing. Enforce a strict protocol allowlist BEFORE evaluating the hostname. Use strict equality (`=== 'domain.com'`) combined with strict suffix matching (`.endsWith('.domain.com')`) for subdomains to ensure the true host is targeted. Allow safe relative paths explicitly if required by the application.
