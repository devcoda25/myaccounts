## 2024-05-15 - [CRITICAL] Open Redirect / SSRF Bypass via URL parsing and `.includes`
**Vulnerability:** Core URL validation in `isValidUrl` and `sanitizeUrl` relied on `parsed.hostname.includes('evzone')`. This was vulnerable to Open Redirect and SSRF because an attacker could use domains like `evzone.com.attacker.com`, which would pass the `.includes` check. Furthermore, failing to sanitize out newlines before passing user input to `new URL()` could result in bypassed validation.
**Learning:** `new URL()` behaves differently with malformed inputs, sometimes failing open or assigning incorrect components. A naive `.includes()` check for hostnames is highly vulnerable to subdomain hijacking or maliciously crafted domains.
**Prevention:** Always sanitize inputs (e.g. `url.replace(/[\n\r\t]/g, '')`) before parsing them as URLs. Validate domains using an exact match (`===`) or a strictly anchored regex (e.g., `/^([a-z0-9-]+\.)*(evzone\.com|evzone\.app|evzonemarketplace\.com)$/i`) to prevent bypasses. Ensure explicit validation checks (`isValidUrl(redirectUri)`) are present directly at sinks where `window.location.href` is dynamically assigned.
