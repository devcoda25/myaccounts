## 2025-02-09 - Sentinel: Fix URL Validation and Sanitization Bypasses
**Vulnerability:** The `isValidUrl` and `sanitizeUrl` functions in `src/sanitizers/url.ts` use loose matching for hostname validation (`parsed.hostname.includes('evzone.com')`), which allows SSRF and Open Redirect bypasses (e.g., `evzone.com.attacker.com`). Furthermore, the `sanitizeUrl` function processes protocols dynamically without enforcing a strict protocol allowlist, meaning `javascript:` URIs pass through when `parsed.protocol !== 'https:'`, allowing XSS (`javascript://evzone.com/%0Aalert(1)`).
**Learning:** `includes()` or loose pattern matching should never be used for hostname validation. The `URL` constructor allows `javascript:` protocols, which parse normally, bypassing domain checks when domain names are placed within the protocol paths.
**Prevention:** Always use strict exact matching (`===`) or strict suffix matching (`endsWith()`) for domains. Always enforce a strict protocol allowlist (`['http:', 'https:']`) explicitly before running domain-specific logic.
