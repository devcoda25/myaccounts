## 2023-11-20 - URL Validation Bypass (Open Redirect/SSRF & XSS)
**Vulnerability:** Weak URL validation allowed bypasses via domain substring matching (`.includes('evzone.com')` allowed `evzone.com.attacker.com`) and allowed dangerous protocols (like `javascript:alert(1)//evzone.com`) because `URL` constructor handles `javascript:` by leaving the hostname empty (which bypassed naive checks or just returned truthy if not checked).
**Learning:** Using `.includes` for domain validation is insecure. The JavaScript `URL` API is forgiving with malicious protocols like `javascript:` and does not throw errors, allowing them to bypass checks that don't explicitly validate the `.protocol` property against a strict allowlist.
**Prevention:** Always use strict Regex (e.g., `/^([a-z0-9-]+\.)*domain\.com$/i`) or exact equality `===` for domain matching. Always explicitly check `url.protocol` against an allowlist (e.g., `['http:', 'https:']`) before assuming a parsed URL is safe. Allow fallback for safe relative paths explicitly if needed.
