## 2026-11-07 - URL Sanitization: Loose Hostname Matching and Protocol Bypasses
**Vulnerability:** URL sanitization functions (`isValidUrl`, `sanitizeUrl`) used loose hostname matching (`parsed.hostname.includes('evzone.com')`) allowing bypasses (e.g., `evzone.com.evil.com`). The functions also parsed arbitrary protocols like `javascript:` without rejecting them correctly in all paths, opening the door for XSS bypasses.
**Learning:** Checking for hostname inclusion using `.includes()` is a common SSRF/Open Redirect security trap, since it permits any domain containing the target substring. Additionally, the `URL` constructor does not enforce HTTP/HTTPS by default, enabling `javascript:` execution if not strictly checked first.
**Prevention:** Always enforce strict domain suffix matching (`=== 'evzone.com' || .endsWith('.evzone.com')`) and an explicit protocol allowlist (`['https:', 'http:']`). Prior to passing input to the `URL` constructor, strip whitespace like newlines to prevent parsing bypasses.
