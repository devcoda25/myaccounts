## 2024-11-20 - [URL Validation SSRF and Open Redirect Vulnerability]
**Vulnerability:** URL validation for trusted domains using `.includes('evzone.com')` allowed attackers to bypass checks using malicious domains like `evzone.com.attacker.com` or `attacker.com/evzone.com`. Additionally, `sanitizeUrl` lacked a protocol allowlist, allowing `javascript:` URLs to pass through if parsed improperly or to be executed if returned directly.
**Learning:** Naive string matching on hostnames is an insufficient security mechanism and can lead to SSRF or Open Redirects. `new URL(url)` parses malicious protocols like `javascript:` without throwing errors, making it critical to strictly check the parsed protocol against an allowlist before using the parsed URL. Further, parsing can be bypassed by injecting whitespace characters like `\n`.
**Prevention:** Always use strict domain exact matching or strict Regex matching for URL domain validation. Enforce a strict protocol allowlist prior to checking domains or performing URL transformations, and strip whitespace from inputs before parsing to prevent parser confusion.
