## 2024-05-16 - Prevented Open Redirect and SSRF via Weak URL Validation
**Vulnerability:** The `isValidUrl` and `sanitizeUrl` functions used weak `.includes()` checks for hostname validation (e.g., `parsed.hostname.includes('evzone.com')`), allowing bypasses using domains like `evzone.com.attacker.com`. Additionally, `sanitizeUrl` attempted to mutate special protocols like `javascript:` directly instead of using a strict allowlist. Path traversal bypasses were also possible via backslashes since route segment validation only blocked forward slashes.
**Learning:** Naive `.includes()` checks are insufficient for domain validation and lead to SSRF and Open Redirect vulnerabilities. Bypasses via URL modifications like protocol injection (e.g., `javascript:alert(1)//evzone.com`) are possible when using the standard `URL` constructor if the protocol isn't strictly verified first.
**Prevention:** Always use strict regex or exact string matching for domains, and strictly allowlist protocols (e.g., `http:`, `https:`). Ensure relative paths and segment parameters are validated against strict alphanumeric regexes (e.g., `/^[a-zA-Z0-9-_]+$/`) instead of simply excluding explicit slash characters.
