## 2024-05-20 - SSRF and XSS Bypass in URL Validation
**Vulnerability:** URL validation (`isValidUrl` and `sanitizeUrl`) used `.includes()` for hostname checking, allowing SSRF/Open Redirects via `attacker-evzone.com` or `evzone.com.attacker.com`. Furthermore, it didn't strip whitespace or validate the protocol before accessing the parsed URL, allowing XSS bypasses like `javascript:alert(1)//evzone.com`. Finally, it crashed for valid relative paths on client-side routing.
**Learning:** The native `URL` constructor parses `javascript:` payloads without throwing errors, making the hostname empty. Always enforce strict protocol allowlists before evaluating hostnames. Additionally, `.includes()` is dangerous for domain validation; always use exact matching combined with strict `.endsWith('.domain.com')` matching for subdomains.
**Prevention:** Use strict equality (`===`) and strict suffix matching (`endsWith('.domain.com')`) for hostnames. Implement explicit, robust checks for safe relative URLs (ignoring `//` and `/\`) and enforce strict protocol allowlists (`['http:', 'https:']`) prior to domain evaluation.
