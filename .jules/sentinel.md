## 2024-06-15 - [SSRF/Open Redirect via weak Domain Validation in `isValidUrl`]
**Vulnerability:** The `isValidUrl` function relies on `parsed.hostname.includes('evzone.com')` to validate URLs. This allows SSRF and Open Redirect attacks because an attacker can supply URLs like `https://evzone.com.attacker.com` which successfully pass the check.
**Learning:** Using string manipulation methods like `.includes()` for URL/domain validation is insecure because it does not enforce strict subdomain boundaries or exact matches, allowing malicious domains to bypass the validation simply by containing the string. Furthermore, the Javascript URL constructor will parse `javascript:alert(1)//evzone.com` as having `javascript:` protocol with an empty hostname and pathname `alert(1)//evzone.com`. The first check prevents this by validating the protocol, but the second check fails to prevent domains ending with attacker.com.
**Prevention:** Always use exact matching (`===`) or strict Regex matching (e.g. `/^([a-z0-9-]+\.)*(evzone\.com|evzone\.app|evzonemarketplace\.com)$/i`) for domain validation to ensure the hostname belongs precisely to the trusted domain or its authorized subdomains. Validate the protocol against an explicit allowlist (like `http:` and `https:`) before any domain checks.
