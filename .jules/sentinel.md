
## 2024-06-01 - Prevent Open Redirect and Path Traversal Bypasses
**Vulnerability:** The application was vulnerable to Open Redirect and Path Traversal bypasses because URL path segment validation relied on weak substring checks (`!segment.includes('/')`), and domain validation relied on weak string inclusion (`hostname.includes('evzone.com')`). This allowed attackers to bypass checks using backslashes (`\`) for path traversal or malicious subdomains (`evzone.com.attacker.com`) and javascript protocol mutation.
**Learning:** `String.prototype.includes()` is insufficient for security-critical validation, especially for hostnames or path segments, as attackers can easily craft payloads that contain the required substring while completely changing the semantic meaning of the string. Additionally, the JavaScript `URL` API silently accepts protocols like `javascript:` even if they contain weird formatting (like newline injection), making protocol allowlisting and whitespace stripping crucial.
**Prevention:** Always validate dynamic URL segments against a strict character allowlist regex (e.g., `/^[a-zA-Z0-9-_]+$/`). For domains, use exact matching (`===`) or strict Regex matching (e.g., `/^([a-z0-9-]+\.)*(trusted\.com)$/i`) and explicitly check the protocol (`https:`, `http:`) from an allowlist. When resolving paths dynamically, strip out all control characters and whitespaces before validation to prevent injection bypasses. Wrap user-supplied `window.location.href` assignments in an `isValidUrl()` condition and use internal routing as a safe fallback.
