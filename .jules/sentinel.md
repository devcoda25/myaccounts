
## 2025-06-12 - Prevent SSRF and Open Redirect Bypasses via URL Parsing and includes()
**Vulnerability:** The application was vulnerable to Open Redirect and SSRF bypasses because URL hostnames were validated using `.includes('evzone.com')` instead of strict matching. Additionally, the native JavaScript `URL` constructor allows `javascript:` protocols to pass without throwing errors, and whitespace injection (like `\n` or `\r`) could be used to bypass domain checks if the URL wasn't properly sanitized before parsing. Unvalidated user-supplied `redirect_uri` parameters were then being assigned directly to `window.location.href`.
**Learning:** Naive `.includes()` checks are easily bypassed (e.g., `evzone.com.attacker.com`). Furthermore, relying solely on `try { new URL(url) }` does not guarantee a safe or functional HTTP/HTTPS URL, as it accepts other protocols. Whitespace characters can cause unexpected parsing behavior in the `URL` constructor, creating bypass vectors. Dynamic routing using `window.location.href` must be wrapped in strict validation, providing safe client-side routing fallbacks (e.g., `navigate()`) on failure.
**Prevention:** Always validate domains using exact matching or strict Regex (e.g., `/^([a-z0-9-]+\.)*(evzone\.com|evzone\.app|evzonemarketplace\.com)$/i`). Before parsing URLs with `new URL()`, explicitly strip out whitespace characters (`\n`, `\r`, `\t`). Always explicitly allowlist permitted protocols (`http:`, `https:`). Never assign unvalidated query parameters to `window.location.href`.
