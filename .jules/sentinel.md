## 2026-10-19 - URL Validation Bypass via Substring Match
**Vulnerability:** URL validation in `isValidUrl` and sanitization in `sanitizeUrl` used loose substring matching (`.includes('evzone.com')` and `.includes('evzone')`). This allows bypasses using domains like `evzone.com.malicious.com` or `malicious-evzone.com`, potentially leading to Server-Side Request Forgery (SSRF) and Open Redirects. Additionally, the `URL` constructor allows the `javascript:` protocol, which can result in XSS if an attacker provides a URL like `javascript://evzone.com/%0aalert(1)` because `parsed.hostname` would equal `evzone.com`.
**Learning:** Using `.includes()` for checking hostnames or domains is inherently unsafe. Also, parsing with the `URL` constructor without strictly allowing safe protocols leaves the application vulnerable to javascript injection attacks.
**Prevention:** Always use strict exact matching (`===`) or suffix matching (`.endsWith()` for subdomains) when validating domains. Explicitly enforce safe protocol allowlists (`['http:', 'https:']`) *before* trusting the hostname, and trim any whitespace/newline characters from the URL string prior to parsing.
