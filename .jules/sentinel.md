## 2024-11-22 - Prevent Open Redirects via Strict URL Validations
**Vulnerability:** The `isValidUrl` validation helper function in `src/sanitizers/url.ts` used `.includes('evzone.com')` on `parsed.hostname` for validation. This naive check is vulnerable to Open Redirect and SSRF bypasses via subdomains such as `evzone.com.attacker.com`. Additionally, three React components directly mapped parsed or requested parameters to `window.location.href` without routing validation checking first (`src/features/auth/continue/Index.tsx`, `src/features/auth/signed-out/Index.tsx`, and `src/features/apps/Apps.tsx`).
**Learning:** Checking for substrings within hostnames allows for dangerous bypasses. `String.prototype.includes` can be manipulated by prepending or appending attacker domains to the original keyword string when passing external payloads to window assignment hooks.
**Prevention:** Always use exact matching (`===`) or strict Regular Expressions anchored to start/end `^...$` to validate domain names prior to sensitive DOM actions, especially client-side redirects using assignments such as `window.location.href`. Validate inputs prior to action calls instead of allowing unvalidated state modifications.
