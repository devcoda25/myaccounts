## 2024-06-19 - [Open Redirect via Subdomain Bypass in isValidUrl]
**Vulnerability:** The `isValidUrl` utility used `.includes('evzone.com')` to validate redirect URLs. This was vulnerable to bypassing via attacker-controlled domains (e.g., `https://evzone.com.attacker.com` or `https://attacker-evzone.com`). Additionally, multiple auth-related files (`ContinueToAppV4`, `SignedOutPage`) assigned `window.location.href` to user-supplied query parameters directly without invoking validation at all.
**Learning:** Naive `.includes()` checks on hostnames allow attackers to trivially bypass Open Redirect and SSRF mitigations. Sinks like `window.location.href` must be guarded directly rather than relying on assumed upstream validation.
**Prevention:** Always use exact hostname matching (`===`) or strict Regex matching anchored to the start and end of the hostname (e.g., `/^([a-z0-9-]+\.)*evzone\.com$/i`) when validating allowed redirect domains. Ensure dynamic assignments to navigation APIs (like `window.location.href`) strictly require a positive validation check (e.g., `isValidUrl`) with a safe internal routing fallback.
