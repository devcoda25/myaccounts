## 2024-05-30 - Fix URL Validation Open Redirect and XSS Bypasses
**Vulnerability:** The application was vulnerable to Open Redirects and potential XSS because `isValidUrl` used weak `.includes('evzone.com')` validation, which allowed subdomains like `evzone.com.attacker.com`. Additionally, `sanitizeUrl` relied on `URL` parsing which accepts protocols like `javascript:`, and failed to explicitly reject them.
**Learning:** When using the JavaScript `URL` constructor, modifying `url.protocol` fails silently for special schemes like `javascript:`. Furthermore, `new URL("javascript:alert(1)//evzone.com")` creates a valid `javascript:` protocol with an empty hostname, circumventing naive hostname validation if the protocol isn't strictly validated first. Also, using `.includes` for domain validation is deeply insecure.
**Prevention:** Always use exact matching or strict Regular Expressions (`/^([a-z0-9-]+\.)*(domain\.com)$/i`) for hostname validation. Always validate protocols against an explicit allowlist (e.g., `['http:', 'https:']`) before attempting to process the URL object, as parsing malicious URLs does not throw errors.
