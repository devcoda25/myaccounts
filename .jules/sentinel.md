## 2026-11-09 - URL Validation and Sanitization Bypasses
**Vulnerability:** The `isValidUrl` and `sanitizeUrl` functions used loose matching (`.includes`) for hostname verification, allowing SSRF/Open Redirects via domains like `not-evzone.com`. Additionally, `sanitizeUrl` lacked protocol restrictions, allowing `javascript:` URIs leading to XSS. Missing whitespace stripping also permitted newline/tab injection bypasses.
**Learning:** `new URL()` allows `javascript:` protocols (with empty hostnames) and ignores certain whitespace characters during parsing, which can bypass loose hostname checks and permit XSS if strict protocol allowlists and exact hostname matching are not enforced.
**Prevention:** Always strip whitespace (`url.replace(/[\n\r\t]/g, '').trim()`) before parsing. Always enforce a strict protocol allowlist (e.g., `['http:', 'https:']`) immediately after parsing. Use exact matching (`===`) or strict suffix matching (`.endsWith()`) for hostnames, avoiding `.includes()`.
