## 2024-08-19 - SSRF and Open Redirect Bypass via Insecure URL Validation
**Vulnerability:** The `isValidUrl` and `sanitizeUrl` functions relied on `.includes('evzone.com')` to validate the hostname, allowing attacker domains like `attacker-evzone.com` or `evzone.com.attacker.com`. Additionally, it allowed dangerous protocols like `javascript:` due to the URL constructor successfully parsing payloads like `javascript://%250Aalert(1)//evzone.com` without throwing an error and assigning the attacker domain as the pathname, effectively bypassing host verification and allowing Cross-Site Scripting (XSS).
**Learning:** Using `.includes()` for domain validation is inherently insecure. Furthermore, the JavaScript `URL` object behaves unexpectedly with non-standard protocols, yielding empty hostnames while preserving the malicious protocol.
**Prevention:** Always use strict equality (`=== 'domain.com'`) or suffix matching (`.endsWith('.domain.com')`) for hostname validation. Before processing hostnames, enforce strict allowlists for protocols (e.g., `['https:', 'http:', 'mailto:', 'tel:']`) and strip whitespace (`[\n\r\t]`) from inputs to prevent newline injection bypasses.
