## 2024-05-15 - Insecure Fallback in Cryptographically Secure Random Number Generation
**Vulnerability:** Security-sensitive functions (`safeRandomBytes`, `mkTempPassword`, Passkey generation) used an insecure fallback to `Math.random()` when `window.crypto.getRandomValues` failed, silently generating predictable values instead of failing securely.
**Learning:** In environments where `window.crypto` is unavailable or fails, silently falling back to a non-cryptographically secure pseudo-random number generator (PRNG) like `Math.random()` completely undermines the security guarantees expected by the caller (e.g., for generating passwords, WebAuthn challenges, or 2FA codes). Predictable random values in these contexts can lead to severe security breaches, such as authentication bypass or session hijacking.
**Prevention:** Cryptographically secure functions MUST fail securely. If a secure random number generator is required but unavailable, the function should explicitly throw an error (e.g., `throw new Error("Secure random number generation is not supported")`) rather than silently returning insecure values. The calling code should then handle this error appropriately.
