## 2024-03-05 - Insecure URL Validation and Sanitization (SSRF / Open Redirect / XSS)
**Vulnerability:** The `isValidUrl` and `sanitizeUrl` functions in `src/sanitizers/url.ts` use `parsed.hostname.includes('evzone')` or `parsed.hostname.includes('evzone.com')` to validate URLs. This allows attackers to bypass validation using domains like `attacker-evzone.com` or `evzone.com.attacker.com`. Additionally, `sanitizeUrl` fails to enforce a protocol allowlist when catching invalid protocols, allowing `javascript:alert(1)` to be returned unmodified if it doesn't match the `https:` upgrade logic. Finally, neither function trims whitespace, which can be used to bypass `new URL()` parsing in some environments, and they don't properly handle safe relative paths.
**Learning:** Using `.includes()` for hostname validation is a critical security flaw because it performs a substring match rather than checking the actual domain hierarchy.
**Prevention:** Always use strict equality (`=== 'evzone.com'`) or strict suffix matching (`.endsWith('.evzone.com')`) for hostname validation. Enforce explicit protocol allowlists and strip whitespace before URL parsing.
