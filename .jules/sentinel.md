## 2024-11-28 - [Open Redirect and SSRF in URL validation]
**Vulnerability:** `isValidUrl` used a weak `.includes('evzone.com')` allowing bypasses like `attacker-evzone.com` or `evzone.com.attacker.com`. Open redirects existed in `continue/Index.tsx` and `signed-out/Index.tsx` by assigning `window.location.href` to user-controlled URLs without validation.
**Learning:** `new URL(url)` correctly parses `javascript:alert(1)//evzone.com` with protocol `javascript:` and empty host, requiring strict protocol allowlists *before* host verification. `URL` constructor throws on relative URLs, meaning safe relative URLs must be parsed carefully before invoking `new URL`.
**Prevention:** Always use strict equality (`===`) and strict suffix matching (`.endsWith('.domain.com')`) for domains. Always enforce protocol allowlists (`['https:', 'http:']`). When dealing with unvalidated redirect URIs in React components, always run them through a strict validation function like `isValidUrl` before setting `window.location.href`.
