## 2024-05-25 - Prevented SSRF and Open Redirect Bypasses via Weak Domain and Path Validation
**Vulnerability:** The application was vulnerable to SSRF and Open Redirect bypasses because `redirect_uri` validation in `src/sanitizers/url.ts` relied on `.includes('evzone.com')`, which would incorrectly allow domains like `evzone.com.attacker.com`. Additionally, URL paths like the one in `PatchOidcResume.tsx` were validated using `!segment.includes('/')`, which could be bypassed using backslashes to traverse paths or execute redirects. In `Index.tsx` files for `/auth/continue` and `/auth/signed-out`, URLs were passed directly to `window.location.href` without `isValidUrl` checks.
**Learning:** Checking for substrings or excluding specific characters (like `/`) is insufficient for domain and path security. It leaves edge cases (like trailing dots, backslashes, or malicious subdomains) that allow attackers to bypass checks and redirect users to malicious sites or execute path traversals.
**Prevention:** Always use strict regular expressions with bounded matching (e.g., `/^([a-z0-9-]+\.)*(evzone\.com|evzone\.app|evzonemarketplace\.com)$/i`) to validate domains, ensuring exact structural matches. For URL path segments, rely on strict allowlists (`/^[a-zA-Z0-9-_]+$/`) instead of denylisting (`!includes('/')`). When dynamic URLs must be assigned to `window.location.href`, they must be explicitly validated (using `isValidUrl`) and have secure fallbacks (using `navigate()` for internal routing) if validation fails.
