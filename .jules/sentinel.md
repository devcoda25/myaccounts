## 2026-09-29 - Prevent SSRF and Open Redirect bypasses using strict hostname checks
**Vulnerability:** The `isValidUrl` function allows any hostname that simply includes the string "evzone.com", such as `https://attacker-evzone.com` or `https://evzone.com.attacker.com`. This is a classic vulnerability for SSRF (Server-Side Request Forgery) and Open Redirect attacks. Additionally, the `isValidUrl` function parses the URL directly without explicitly stripping whitespace or newline characters, which can lead to bypasses via URL injection, though it does check for the correct protocol. The memory specifies: "When validating hostnames to prevent Server-Side Request Forgery (SSRF) or Open Redirects, never use `.includes('domain.com')` as it allows bypasses via malicious domains (e.g., `attacker-domain.com` or `domain.com.attacker.com`). Use strict equality (`=== 'domain.com'`) combined with strict suffix matching (`.endsWith('.domain.com')`) for subdomains." And for newline/whitespace: "Always strip whitespace characters (e.g., `url.replace(/[\n\r\t]/g, '').trim()`) first to prevent newline or tab injection bypasses."
**Learning:** Checking for hostname inclusion (`.includes('domain.com')`) is fundamentally flawed and allows domain spoofing. URL parsing can also be tricky with newlines.
**Prevention:** Use exact domain matching (`hostname === 'evzone.com'`) or explicit subdomain matching (`hostname.endsWith('.evzone.com')`). Always sanitize whitespace from URLs before passing them to the `URL()` constructor.
