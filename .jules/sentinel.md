## 2024-05-24 - [CRITICAL] Open Redirect in `isValidUrl` and Auth Flows
**Vulnerability:** The `isValidUrl` function in `src/sanitizers/url.ts` only checked if the hostname included the string 'evzone.com' (`parsed.hostname.includes('evzone.com')`), allowing Open Redirects via domains like `attacker-evzone.com` or `evzone.com.attacker.com`. Additionally, components like `src/features/auth/signed-out/Index.tsx` directly assigned `redirectUri` parameters to `window.location.href` without verifying them against `isValidUrl`.
**Learning:** `String.prototype.includes()` is insufficient for hostname validation. Strict equality or suffix checking (`endsWith('.evzone.com')`) is necessary. Furthermore, all sinks that redirect the user (e.g., `window.location.href = ...`) must validate dynamically provided URLs, wrapping the assignment in a condition like `if (isValidUrl(redirectUri))`.
**Prevention:** Always use strict domain matching when validating URLs, and never assign unvalidated user input to `window.location.href`. Provide safe fallbacks using internal routing (e.g., `navigate('/app')`).
