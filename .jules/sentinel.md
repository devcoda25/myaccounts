## $(date +%Y-%m-%d) - Fix URL validation and sanitization bypasses
**Vulnerability:** The URL validation and sanitization functions (`isValidUrl`, `sanitizeUrl`) in `src/sanitizers/url.ts` were vulnerable to SSRF/Open Redirects via substring matching (`.includes('evzone.com')` allowed `evzone.com.attacker.com`) and Cross-Site Scripting (XSS) because they failed to enforce a strict protocol allowlist, allowing dangerous protocols like `javascript:` to pass through the `URL` constructor.
**Learning:** The `URL` constructor is not a security boundary; it merely parses input according to standard RFCs. Malicious payloads like `javascript:alert(1)//evzone.com` parse without error (with an empty hostname). Validating domains via `.includes()` is dangerous because it matches anywhere in the string.
**Prevention:** Always enforce a strict protocol allowlist (e.g., `['https:', 'http:']`) before evaluating hostnames. Use strict equality (`=== 'domain.com'`) combined with strict suffix matching (`.endsWith('.domain.com')`) for subdomains instead of `.includes()`. Explicitly handle and allow safe relative paths (e.g., `/path`) before URL parsing, while stripping whitespaces and rejecting protocol-relative URLs (`//attacker.com`).
