## 2024-05-27 - URL Validation and Path Traversal Bypasses
**Vulnerability:** Open Redirect, SSRF, and Path Traversal vulnerabilities due to weak URL validation using `.includes()` for domain checks, lack of protocol allowlisting before domain validation, and using `!segment.includes('/')` for path validation which can be bypassed using backslashes.
**Learning:** The `URL` constructor does not throw errors on `javascript:` schemas, so protocol must be checked *before* hostnames. String `.includes('domain.com')` is bypassed by subdomains like `domain.com.attacker.com`. Finally, backslashes (`\`) bypass simple forward slash checks in routing segments.
**Prevention:** Always use strict regex domain validation like `/^([a-z0-9-]+\.)*(domain\.com)$/i` or strict equality `===`. Use explicit protocol allowlists `['http:', 'https:']`. For dynamic URL path segments, use regex allowlisting `/^[a-zA-Z0-9-_]+$/` instead of explicitly blocking characters. For relative URL handling, explicitly allow safe relative paths while blocking protocol-relative `//` and `/\`.
