## 2024-05-18 - URL Validation SSRF and Open Redirect Bypass
**Vulnerability:** The URL validation logic (`isValidUrl` and `sanitizeUrl`) was vulnerable to bypasses because it relied on `.includes('evzone.com')` for domain matching. This allowed URLs like `https://evzone.com.attacker.com` to pass as valid. Additionally, `URL` constructor parsing anomalies with protocols like `javascript:alert(1)//evzone.com` could bypass naive host checks.
**Learning:** Using string methods like `.includes` or `.endsWith` without careful consideration of subdomains and top-level domains leads to SSRF and Open Redirect vulnerabilities. Additionally, the JavaScript `URL` object allows empty hostnames when certain protocols (like `javascript:`) are used, causing properties like `hostname` to be empty strings.
**Prevention:** Always use exact matching (`===`) or strict Regex matching (e.g., `/^([a-z0-9-]+\.)*(evzone\.com|evzone\.app|evzonemarketplace\.com)$/i`) for trusted domains. Always strip whitespace before validating URLs. Always explicitly allow safe relative paths if required by the application to avoid breaking functionality when migrating to strict absolute URL checks. Ensure that the protocol is explicitly validated against a tight allowlist (e.g., `http:`, `https:`, `mailto:`, `tel:`).
