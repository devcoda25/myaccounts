
## 2024-06-03 - Open Redirect/SSRF Bypass via Weak Hostname Validation
**Vulnerability:** The `isValidUrl` function in `src/sanitizers/url.ts` used `.includes('evzone.com')` to validate the hostname of a URL. This allowed an attacker to bypass validation by providing a domain like `evzone.com.attacker.com` which still satisfies the check. This weak validation was used for redirects (`window.location.href`), opening the door to Open Redirects, and potentially Server-Side Request Forgery (SSRF) elsewhere.
**Learning:** Naive substring matching (like `.includes()`) for URL domain validation is fundamentally insecure because it does not anchor the string matching correctly to domain boundaries. It allows matching arbitrary prefixes or suffixes. Furthermore, parsing malicious URIs without strict schema allow-lists can sometimes yield unexpected results leading to logic bypass.
**Prevention:** Always use strict regex matching (e.g., `/^([a-z0-9-]+\.)*(evzone\.com|evzone\.app|evzonemarketplace\.com)$/i`) or direct equality matching to validate trusted domain names. Additionally, when accepting relative paths as safe redirects, explicitly allow only those starting with `/` (while denying `//`, `/\`, or `/.`) and sanitize newline/tab characters to prevent protocol parsing bypasses.
