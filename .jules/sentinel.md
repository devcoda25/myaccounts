## 2026-09-02 - [XSS and SSRF vulnerabilities in URL parsing]
**Vulnerability:** The isValidUrl and sanitizeUrl functions were vulnerable to XSS and SSRF. They used .includes() for hostname matching, allowing bypasses (e.g., attacker-evzone.com). They also did not enforce a protocol allowlist on the parsed URL in sanitizeUrl, allowing javascript:alert(1)//evzone.com to be parsed as a valid URL with the javascript: protocol.
**Learning:** The JS URL constructor parses javascript:alert(1)//domain.com without error, returning a javascript: protocol and an empty hostname. Also, .includes('domain.com') is insecure for validating domains, and allows bypasses via subdomains of an attacker site.
**Prevention:** Always enforce a strict protocol allowlist (e.g., ['https:', 'http:']) before evaluating the hostname to prevent bypasses. Use strict equality (=== 'domain.com') combined with strict suffix matching (.endsWith('.domain.com')) for subdomains. Ensure whitespace is stripped before parsing, and explicitly handle safe relative paths.
