## 2026-11-09 - [URL Validation Open Redirect & SSRF via Loose Matching]
**Vulnerability:** URL validation and sanitization routines used loose `.includes('domain.com')` checks on the parsed hostname, permitting bypasses via subdomains on attacker-controlled domains (e.g., `domain.com.evil.com`). It also lacked strict whitespace stripping, potentially leading to newline injection, and failed to explicitly restrict protocols before returning early in sanitization functions.
**Learning:** `URL.hostname` includes the entire host string. Using `.includes()` on it is fundamentally insecure for validation. The `new URL()` constructor also accepts trailing/leading whitespace and parses unexpected protocols (like `javascript:`) without throwing errors.
**Prevention:** Always enforce strict hostname validation using exact matching (`===`) or strict suffix matching (`.endsWith('.domain.com')`). Always explicitly allowlist permitted protocols (e.g., `['http:', 'https:']`) immediately after parsing. Strip all whitespace (`[\n\r\t]`) prior to passing inputs to the `URL` constructor.
