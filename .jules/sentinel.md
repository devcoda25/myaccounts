## 2024-05-24 - [CRITICAL] Open Redirect / SSRF in URL Sanitizers
**Vulnerability:** The `isValidUrl` and `sanitizeUrl` utilities insecurely parsed domains using `.includes('evzone.com')` and allowed the `javascript:` protocol to bypass filters when `URL` construction returned an empty hostname.
**Learning:** Naive substring matching for domains (e.g., `includes`) allows simple bypasses (e.g., `evzone.com.attacker.com` or `attacker-evzone.com`). Additionally, the native `URL` parser allows `javascript:` protocols, which can result in XSS if returned unfiltered, and natively throws TypeErrors when parsing relative paths, which developers often attempt to bypass insecurely.
**Prevention:** Always enforce a strict, explicit protocol allowlist (e.g., `['https:', 'http:']`) before evaluating hostnames. For subdomains, use strict equality (`===`) or suffix matching (`.endsWith('.domain.com')`). Handle safe relative paths explicitly at the top of the function to avoid `URL` parsing TypeErrors.
