## 2024-05-18 - [CRITICAL] Open Redirect & SSRF via Weak URL Domain Validation
**Vulnerability:** Weak domain matching (`parsed.hostname.includes('evzone.com')`) allowed SSRF/Open Redirect bypasses via subdomains like `evzone.com.attacker.com` and lacked URL parsing safeguards for whitespace injection. Unvalidated `redirect_uri` variables from the querystring were directly assigned to `window.location.href`.
**Learning:** `String.prototype.includes()` is insufficient for hostname validation. The JavaScript `URL` constructor allows whitespace characters (like newlines) before the protocol, bypassing strict protocol checks when combined with `javascript:`. Open Redirect flows mapping direct user input to navigation APIs must validate the target fully.
**Prevention:** Strictly validate hostnames against safe domains using anchored exact regular expressions (`^...$`). Strip whitespace before invoking `new URL()`. Use robust client-side internal routing (`navigate`) for invalid fallback paths rather than untrusted external redirects.
