## 2024-05-18 - Fix Open Redirect / SSRF vulnerability in URL Validation
**Vulnerability:** The `isValidUrl` and `sanitizeUrl` functions used `.includes('evzone.com')` to validate the hostname. This is vulnerable to bypasses because it will match a domain like `evzone.com.attacker.com` or `attackerevzone.com`. The JavaScript `URL` object allows leading whitespaces that could be used for other bypasses.
**Learning:** Naive substring matching on hostnames is insufficient for domain validation. Strict Regex or exact matching is necessary. Whitespace in URLs should also be stripped when doing custom validation before parsing them into `URL` objects. Safe relative paths should be explicitly allowed for legitimate client-side routing.
**Prevention:** Use exact domain matching or strict Regex (like `/^([a-z0-9-]+\.)*(evzone\.com|evzone\.app|evzonemarketplace\.com)$/i`) for domain validation. Always strip whitespace from URLs before processing them. Ensure valid protocols (e.g. 'http:', 'https:') are explicitly allowed.
