## 2024-05-18 - Fix Open Redirect & SSRF Bypass in URL Validator
**Vulnerability:** The `isValidUrl` and `sanitizeUrl` functions used naive `.includes()` checks for hostname validation (e.g., `parsed.hostname.includes('evzone.com')`). This allows attackers to bypass the validation by using subdomains like `evzone.com.attacker.com` or paths disguised in the host if parsed improperly. Furthermore, the JavaScript `URL` constructor parses `javascript:alert(1)//evzone.com` without throwing, assigning `javascript:` as the protocol and allowing potential XSS if the protocol isn't strictly verified first. The unvalidated URLs were directly passed to `window.location.href`.
**Learning:** Naive string matching (`.includes()`) on URLs is insufficient and often leads to Open Redirect or Server-Side Request Forgery (SSRF). Always enforce a strict protocol allowlist and use strict regular expressions with domain boundary anchors (`^` and `$`) for host validation.
**Prevention:** Rely on exact matches (`===`) or anchored Regular Expressions to validate hosts against an allowlist. Pre-process the URL string by stripping whitespace and control characters to mitigate parser discrepancies, and verify safe relative paths explicitly before relying on `new URL()`.
