## 2026-09-21 - Fix SSRF and Open Redirect Vulnerability in URL Sanitization

**Vulnerability:** The `isValidUrl` and `sanitizeUrl` functions in `src/sanitizers/url.ts` used `.includes('evzone.com')` to validate hostnames. This is vulnerable to bypasses because attackers can register domains like `evzone.com.attacker.com` or `attackerevzone.com`, which would pass the validation. Additionally, `sanitizeUrl` did not enforce a strict protocol allowlist, potentially allowing `javascript:` URLs to pass through if the hostname condition was not met or misunderstood. Furthermore, there was no whitespace stripping before URL parsing, which can lead to bypasses via newline characters.
**Learning:** Using `.includes()` for domain validation is a common security pitfall. It matches substrings anywhere in the hostname, allowing attacker-controlled domains to mimic legitimate ones. Also, failing to strip whitespace before using `new URL()` can lead to unexpected parsing behaviors. Always enforce strict protocol allowlists.
**Prevention:** Always use strict equality (`=== 'domain.com'`) combined with strict suffix matching (`.endsWith('.domain.com')`) for subdomains. Strip whitespace characters (`url.replace(/[\n\r\t]/g, '').trim()`) before parsing the URL. Enforce an explicit protocol allowlist (e.g., `['http:', 'https:', 'mailto:', 'tel:']`) and reject anything else.
