## 2026-11-11 - Fix URL validation SSRF/Open Redirect Vulnerability
**Vulnerability:** The `isValidUrl` and `sanitizeUrl` functions in `src/sanitizers/url.ts` were vulnerable to Server-Side Request Forgery (SSRF) and Open Redirect bypasses. They used loose string matching (`.includes('evzone.com')`) for hostname validation and allowed arbitrary protocols like `javascript:` by failing to enforce a strict protocol allowlist. Furthermore, newline characters (`\n`, `\r`, `\t`) could be used to bypass sanitization when parsed by `new URL()`.
**Learning:** `new URL()` parses protocols like `javascript:` without throwing an error and often results in an empty hostname. Loose validation methods like `String.prototype.includes` can easily be bypassed by domains like `evzone.com.evil.com`. Newline characters at the beginning or within URLs can lead to parsing bypasses.
**Prevention:** Always enforce a strict protocol allowlist (e.g., `['http:', 'https:']`) explicitly before performing hostname validation. Use exact matching (`===`) or strict suffix matching (`.endsWith()`) for hostname validation. Always strip whitespace and newline characters (`url.replace(/[\n\r\t]/g, '').trim()`) before parsing URLs.
