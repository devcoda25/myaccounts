## 2026-07-06 - [CRITICAL] Open Redirect / SSRF Bypass via Loose URL Validation
**Vulnerability:** The application was vulnerable to Open Redirect and SSRF because `isValidUrl` used `parsed.hostname.includes('evzone.com')` which could be bypassed with domains like `evzone.com.attacker.com`. Also, failing to restrict the protocol initially allowed attacks via `javascript:`.
**Learning:** Naive substring matching (like `.includes()`) on URLs allows attackers to append or prepend characters to trusted domains. The `URL` constructor parses `javascript:alert(1)//evzone.com` by setting the protocol to `javascript:` and keeping hostname empty, bypassing simple hostname checks if the protocol isn't enforced strictly first.
**Prevention:** Always use strict regular expressions with anchors (e.g. `/^([a-z0-9-]+\.)*evzone\.com$/i`) to match domains exactly. Ensure the protocol is verified against a strict allowlist (`http:`, `https:`) before relying on hostname properties, and strip whitespaces (like newline/tab injection) before parsing.
