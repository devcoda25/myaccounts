## 2024-07-03 - [CRITICAL] Open Redirect / SSRF in URL validation
**Vulnerability:** The `isValidUrl` validation function used `.includes('evzone.com')` allowing bypasses like `evzone.com.attacker.com` and lacked whitespace cleaning allowing `javascript:alert(1)//evzone.com` bypasses. The application was then using unverified URLs by assigning `window.location.href = redirectUri` in Auth flows, introducing Open Redirect and SSRF risks.
**Learning:** URL host validation must strictly match trusted domains using Exact matching or strict regular expressions, rather than `.includes()`. Any unverified URL assigned directly to `window.location.href` must be wrapped in a validation condition and provide a safe fallback using internal routing.
**Prevention:** Use a stricter `isValidUrl` utility which enforces regex hostname checks and explicitly strips whitespace characters. Wrap user-provided `redirectUri` values in validation checks before assigning to `window.location.href`.
