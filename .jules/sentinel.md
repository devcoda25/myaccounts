## 2024-05-29 - Weak URL Domain Validation and JavaScript URL Parsing Quirks
**Vulnerability:** Open Redirect and SSRF bypasses via `.includes()` domain matching and implicit protocol allowance in URL sanitization. For example, `isValidUrl("https://evzone.com.attacker.com")` returns `true`. Further, `sanitizeUrl("javascript:alert(1)//evzone.com")` executes because the `URL` constructor parses `javascript:` as the protocol and assigns an empty hostname, circumventing `parsed.hostname.includes('evzone')` without throwing an error.
**Learning:** Using `String.prototype.includes()` for domain validation is highly vulnerable to suffix bypasses. Additionally, the JavaScript `URL` constructor's behavior around special schemas like `javascript:` requires strict, explicit protocol allowlists *before* attempting to evaluate or mutate properties like `hostname` or `protocol`. Modifying `url.protocol` fails silently for special schemas. Finally, `new URL()` throws an error for relative paths, so robust sanitizers must handle these exceptions gracefully to avoid functional regressions.
**Prevention:** Always validate trusted domains using exact matching (`===`) or strict Regex matching (e.g., `/^([a-z0-9-]+\.)*(evzone\.com)$/i`). Always validate URLs against an explicit allowlist of safe protocols (e.g., `['http:', 'https:', 'mailto:', 'tel:']`) before proceeding with domain checks. Explicitly handle relative paths by catching exceptions from `new URL()` and validating them against a safe regex like `/^\/(?!\/|\.|\\)/`.
