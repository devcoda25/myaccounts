## 2024-05-24 - URL Parser Bypasses (CRLF, Protocol, Subdomain)
**Vulnerability:** The application's core URL sanitation and validation utilities (`sanitizeUrl` and `isValidUrl` in `src/sanitizers/url.ts`) were vulnerable to Open Redirect, SSRF, and XSS. The hostname validation used `.includes('evzone.com')`, allowing bypasses via domains like `evzone.com.attacker.com`. Additionally, a lack of protocol validation in `sanitizeUrl` allowed `javascript:alert(1)` payloads to pass through, and the absence of whitespace stripping exposed the validation to CRLF/obfuscation bypasses when passing values to the `URL` constructor.
**Learning:** `new URL()` in JavaScript is highly permissive. It will parse `javascript:alert(1)//evzone.com` without error, treating `javascript:` as the protocol and leaving the hostname empty or shifting values unexpectedly. Because validation relied solely on the hostname `.includes()`, this allowed the attacker to easily construct payloads that bypass both the HTTPS production guard and standard host boundaries.
**Prevention:** Always strip whitespace (CRLF, tabs) before validation. Enforce a strict protocol allowlist (e.g. `http:`, `https:`, `mailto:`) before evaluating the hostname. Validate subdomains using strict equality (`===`) or exact suffix matching (`.endsWith('.domain.com')`) rather than `.includes()`. Finally, when allowing relative paths through the validation fast-path, explicitly check that they start with `/`, `?`, or `#` and explicitly block protocol-relative paths (`//` or `/\`).
