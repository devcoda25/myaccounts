## 2026-09-22 - URL Validation Bypass via includes() and javascript: protocol
**Vulnerability:** URL validation used `.includes('evzone.com')` which allows bypasses like `evzone.com.attacker.com` or `attacker-evzone.com`. Furthermore, `sanitizeUrl` lacked a strict protocol allowlist, allowing `javascript:alert(1)//evzone.com` XSS bypasses because `new URL()` parses the `javascript:` protocol with an empty hostname.
**Learning:** Never use `.includes()` for domain validation. The `URL` constructor parsing rules can be surprising; it does not throw on `javascript:` URLs and correctly parses the protocol, but the hostname might be empty or unexpected, bypassing hostname checks if protocols aren't strictly filtered first. Whitespace characters like newlines or tabs can also bypass some URL parsing.
**Prevention:** Always enforce a strict protocol allowlist (`['http:', 'https:']`) before evaluating the hostname. Always use strict equality (`=== 'domain.com'`) combined with strict suffix matching (`.endsWith('.domain.com')`) for subdomains. Always strip whitespace before passing to `new URL()`.
