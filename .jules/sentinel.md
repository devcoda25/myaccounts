## 2026-10-13 - [CRITICAL/HIGH] Fix SSRF and Open Redirect bypasses in URL validation
**Vulnerability:** URL validation logic used loosely matched methods like `.includes('evzone.com')` which allowed bypasses such as `evzone.com.attacker.com`. Protocol parsing did not strictly enforce allowlists, allowing malicious protocols like `javascript:`. Newlines and tabs were not stripped before parsing.
**Learning:** Using `.includes()` for hostname validation in URLs is dangerous and leads to SSRF and Open Redirect bypasses. `new URL()` parses `javascript:` without throwing errors, necessitating explicit protocol allowlists. Whitespace characters must be stripped before parsing.
**Prevention:** Always use exact matching (`===`) or strict suffix matching (`.endsWith()` with a leading dot or careful consideration) for hostname validation. Always enforce a strict protocol allowlist (e.g., `['http:', 'https:']`). Explicitly strip whitespace characters using `url.replace(/[\n\r\t]/g, '').trim()` before parsing URLs.
